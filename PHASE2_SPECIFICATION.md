## 2. Persistent Storage Layer (P2-01)

### 2.1 Requirements
- Memory system: episodic and semantic memories persisted across restarts
- Audit system: hash-chained audit log persisted with tamper detection intact
- State plane: belief state history persisted for replay
- All storage must maintain Apache 2.0 license compatibility

### 2.2 Backend Options (FOUNDER DECISION REQUIRED)

| Option | License | Pros | Cons |
|--------|---------|------|------|
| SQLite | Public domain | Zero config, file-based, ACID | Limited concurrency, no network |
| PostgreSQL | PostgreSQL License (BSD-like) | Robust, scalable, JSON support | Requires server setup |
| MongoDB (Community) | SSPL | Document-native, flexible schema | SSPL not OSI-approved; Apache 2.0 compatibility unclear |
| Redis | BSD-3-Clause | Fast, in-memory + persistence | Not designed for persistent audit logs |

**CONFIRMED:** SQLite for Phase 2 (zero infrastructure, Apache 2.0 compatible). PostgreSQL for Phase 3+ when concurrency matters.

## 3. GPT-4o Integration Testing (P2-02)

### 3.1 Requirements

- Verify action proposals generated by GPT-4o pass safety arbitration
- Verify memory embeddings via GPT-4o embedding model

### 3.2 Test Plan

2. Integration test: Full cycle with GPT-4o reasoning (sensor → state → GPT reasoning → arbitration → execution → audit)
3. Resilience test: API timeout/rror → deterministic fallback activates
4. Memory test: GPT-4o embeddings stored and retrieved correctly
